## How a Retro Works

Each year has a **Season** retro (kickoff through the last event) and an **Off-Season** retro (the off-season robot, rebuilds, and experiments).

| Mark | Meaning |
|---|---|
| ✅ **Keep** | Worked well. Became or confirmed a standard. |
| ❌ **Fix** | Hurt us. The standard now says to do it differently. |
| ⚖️ **Mixed** | Real upsides and downsides. The standard says when to use it. |

### End-of-season routine

1. **Write the raw notes.** A quick list, marked Keep, Fix, or Mixed, with the reason for each.
2. **Update the standards.** For each note, add or edit the rule on the matching standards page, with a *Why* and a link back to this season's retro. If a note reverses an old rule, rewrite the rule; don't add a second one.
3. **Write the retro.** Create `docs/seasons/<year>/season.md` or `off-season.md`. List each lesson as one line linking to its standard, then keep the raw notes at the bottom under "Original notes."
4. **Add the page** to `nav` in `mkdocs.yml` and link it from this page.
